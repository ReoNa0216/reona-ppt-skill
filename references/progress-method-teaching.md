# Progress Method Teaching And Comparison

Read when understanding a method or judging a method change is part of the Progress audience's task. Apply this guidance within the workstream's evidence profile, using the existing map, storyboard, and production source.

## Start from the audience's knowledge

Use the brief to identify the scientific and mathematical prerequisites the audience needs taught. Let the requested questions determine explanation depth and comparison dimensions. When understanding a change requires knowing the earlier method, teach that operation before the change and its results. A method explanation can also stand alone without a comparison.

## Connect the real object to a complete example

Introduce the scientific object and analysis unit before its computational or mathematical representation. Explain what the operation acts on, why it is needed, how its inputs are constructed, and what its output means. Define an unfamiliar internal term through that object before using it as shorthand.

Choose a small valid example that follows the actual rule. Keep object identities and units consistent through `input → intermediate values or states → operation or decision → output`. Explain why each calculation produces the intended quantity, including the meaning of its denominator or reference value when relevant. Every number used in the explanation should be traceable within the example. Then connect the output to its use in the method. Split the explanation when a missing prerequisite would otherwise be skipped.

## Give the schematic and notes complementary jobs

Specify what uncertainty the visual should resolve and which objects, transformations, or before/after states must be visible. Actively use image generation when an explanatory schematic will make the operation easier to understand; use native elements for exact labels, arithmetic, or geometry where needed. Check the result against the rule and example, including arrows, values, and object identities.

Keep the essential object and transformation on the slide. Use notes for the intermediate reasoning needed to reproduce and explain the example, including why the output follows. Notes should supply useful logic beyond the visible text; an explanatory page can take the rule or operation itself as its learning takeaway.

## Match comparisons and attribution to evidence

Identify the actual compared objects, versions or procedures, inputs, conditions, and result sources. Check that these answer the user's question. Explain what each change addresses and which behavior it is intended to preserve or alter; distinguish intended behavior from what the recorded results demonstrate.

Choose measures and visualizations for the requested claim. Define the analysis unit, relevant matching or inclusion rules, and denominators. Claims about overall behavior need evidence covering the relevant population, with exclusions stated. Distributional similarity, correlation, and numerical agreement answer different questions; use the measure that establishes the requested property. Make meaningful differences and preserved behavior equally readable, using consistent encodings, comparable scales, and numeric ticks with explicit units.

For performance claims, identify the measured scope, metric, units, conditions, repetitions, and observed variation needed to interpret the result. Overall or stage-level comparisons establish changes at that scope. Attributing an effect to one of several changed factors requires evidence that isolates its contribution. State measured tradeoffs directly and assign causes only where the evidence supports them.

Before production, check whether a listener with the stated background can identify the input, follow the operation through the example, explain the output, and read the requested comparisons. Resolve gaps in the visible explanation or notes, then apply the shared export and consistency review.
